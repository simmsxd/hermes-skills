# Dig Me — 自我挖掘追问技能

## Overview

把"认识自己"从一次性的哲学问题变成一场结构化的证据收集：通过多轮单点追问，逼出具体事件而非抽象形容词，追踪矛盾，最后合成一份基于行为证据的自我画像。

核心原则：**真正的自己不是"想"出来的，是"做"出来、再从做的结果里反推出来的。**

## 模式选择（Session 启动时先判断）

| 模式 | 数据源 | 证据质量 | 触发示例 |
|---|---|---|---|
| 单人（默认） | 用户本人一手回答 | 最高 | "挖掘我" / "dig me" |
| 多人 | 多个对象各自独立 session | 最高 | "给 A 和 B 各跑一次 dig-me" |
| 公开资料 | 网络公开资料 + 用户转述 | 降一至两档 | "分析一下罗永浩" |

**模式判断规则：**
- 未指定对象或对象就是用户 → 单人模式。
- 用户要求同时分析多个在场对象（他们本人能回答） → 多人模式，开多个独立 session。
- 对象不在场、只存在于公开资料或用户转述中 → 公开资料模式，必须先声明证据滤镜（见下）。
- 拿不准时问一句："他本人会来回答，还是只根据公开资料/你的了解分析？"

**多人模式纪律（核心）：**
1. **提问流不混跑。** 每个 session 有独立的矛盾清单和事件库，一次只跑一个对象，跑完生成画像再换下一个。绝不把 A 的答案混进 B 的画像。
2. **画像独立存档。** 每个对象一份画像文件（`dig-me-对象名-YYYY-MM-DD.md`），互不合并。
3. 所有对象跑完后，可按需生成 **交叉产物**（见"交叉产物"节）。
4. 本人是回答者但想分析他人的（用户凭记忆转述对象的行为）→ 按公开资料模式处理证据质量，画像标注"转述滤镜"。

## Session 启动

收到触发词后，按以下顺序开场：

1. 确认模式：问用户想从哪个维度切入（若用户没有明确方向，默认从「能量与满足感」维度开始，因为它最容易给出具体事件）。维度清单见 `references/question-bank.md`。
2. 宣告规则（简短一段）："我会一次只问一个问题。答案请尽量给具体事件，不给形容词。你随时可以说'停'结束并生成画像。"
3. 开始第一问。第一问必须能够以一个具体事件回答（问"什么"和"哪一次"，不问"你觉得你是怎样的人"）。

## 提问纪律（核心，必须遵守）

1. **一次只问一个问题。** 永远不要在一条消息里堆多个问题。
2. **形容词触发追问。** 用户回答中出现"有毅力 / 随和 / 追求完美 / 没有安全感"这类抽象自我评价时，立即追问："说一件具体的事，最好是没人要求你的情况下发生的。"拿到事件才算通过。
3. **深度优先，不广撒网。** 每个答案至少向下追问一层（动机→反例→边界），再换下一个方向。宁可挖透三个点，不蜻蜓点水十个点。
4. **检测回避。** 用户连续两次用"大概 / 其实也没什么 / 我也说不清"敷衍时，换一个更具体的切入角度（从泛化问题切到某个具体时间段的某个具体决定），而不是重复追问。
5. **记录矛盾。** 每轮在内部维护一份矛盾清单：前后答案冲突的地方（如"我不在乎别人评价"但多个事件都在回应他人期待）。不立即纠正，但在第 3 轮后开始温和地呈现："你刚才说 X，但前面提到的 Y 似乎指向相反的方向，这两件事怎么同时成立？"
6. **不评判、不建议。** 追问阶段只收集证据和呈现矛盾。分析留到画像生成阶段。
7. **默认一轮 session 以 8–12 个问题为宜。** 用户要求更深可延长。

## 问题来源

问题从 `references/question-bank.md` 的维度库中选取，但优先基于用户已给出的答案即兴生成追问——问题库里的是方向种子，不是固定问卷。追问质量高于题库覆盖度。

## 画像生成（Session 结束时）

用户说"停 / 差不多了 / 生成画像"或问题轮数达到上限时，输出自我画像。画像必须满足：

1. **只基于本次 session 收集到的具体事件**，不使用用户未提供的泛化描述。
2. 结构：
   - **反复出现的主题**：多个事件中重复出现的模式（列明是哪几个事件支撑的）。
   - **推断出的价值排序**：从情绪强度和实际选择反推（说明推断链）。
   - **行为与自我叙事的偏差**：用户对自己的描述 vs 事件实际指向的差异。
   - **未测试区域**：本次 session 没有覆盖到的维度，下次可切入。
   - **3 个行为实验建议**：可执行的验证动作（如"接下来两周记录每次拖延时真正回避的是什么"），用于在现实中继续收集证据。
3. 语气：直接、具体、以事件为锚。不用"你是一个XX的人"这种定论句式，用"你的事件指向……"。
4. 画像默认保存为 Markdown 文件至**当前工作区根目录**（用户另有指定时从其指定；可用 Glob `dig-me-*.md` 检索全部画像），单人模式文件名 `dig-me-YYYY-MM-DD.md`，多对象文件名 `dig-me-对象名-YYYY-MM-DD.md`，便于跨 session 对比——自我画像的价值随回看次数上升。

## 公开资料模式的附加规则

分析不在场的人物（公众人物或用户认识但未参与对话的人）时，在单人模式纪律之上追加：

1. **先声明证据滤镜（强制）。** 开场必须说明：公开资料是被媒介/本人剪辑过的样本，用户转述叠加了转述者的观察框架，画像本质是"X 视角下的对象"，完整度可能低于 50%。
2. **先跑数据再下结论。** 涉及公众人物时先用网络搜索拉取近期公开动态，不用过时信息做行为分析；每个论断标注证据强度（高：多来源交叉的行为事实 / 中：单一来源 / 低：本人言论与行为存在剪辑可能）。
3. **区分语言账户与行为账户。** 公开人物的言论≠行为，画像以可验证的行为（还款、离职、公开决策）为主锚，言论只作叙事对照。
4. 画像文件命名 `dig-me-对照-对象名.md`，并在文件头部标注"公开资料模式 + 滤镜声明"。

## 交叉产物（多人/多画像跑完后可选）

所有对象画像就绪后，用户可要求生成交叉产物：

1. **双人对照表**：两份画像的核心模式逐项对照（如"判断vs结果"、"对错vs关系"、"内耗水平"），标注哪些是模式差异、哪些只是场景差异。强调是两种结构，不评优劣。
2. **交叉验证**（三方及以上）：让多个熟悉对象 C 的人分别回答关于 C 的问题，两份以上证词的一致处采信度高，冲突处单列"待核实"。适用于团队、合伙关系评估。
3. **协作预警**（合作关系场景）：基于两份画像的模式交集，指出高频摩擦点（如"分离式思维 × 叙事驱动型"的沟通错位）和互补点。预警是假设不是结论，标注需现实验证。
4. 交叉产物保存为独立文件（`dig-me-对照-甲vs乙-YYYY-MM-DD.md`）。

## 跨 Session 使用

第二次及以后触发本技能时：先读取工作区中已有的 `dig-me-*.md` 画像文件（用 Glob 检索 `**/dig-me-*.md`），从未测试区域或上次矛盾清单切入，并回看上次的判断是否被新证据修正。挖掘自己是迭代过程，不是一次性问卷。
